# Decisions

| Date | Decision | Why |
|---|---|---|
| 2026-10-03 | Single user, no backend, data on device (IndexedDB) | Personal use only; privacy; zero running cost |
| 2026-10-03 | PWA instead of a native app | One codebase for phone and desktop; no app store; installs from a link |
| 2026-10-03 | Money stored as integer cents | Avoids floating-point rounding errors |
| 2026-10-03 | Host on GitHub Pages | Free static hosting; deploys from `main` via Actions. Free plans need a public repo for Pages; this is fine because the code holds no personal data. |
| 2026-10-03 | Export/import backup is a core feature | Device-only storage can be lost (cleared browser, lost phone, iOS eviction) |
| 2026-10-03 | On iOS/iPadOS, block use in the browser until the app is installed, with a "Use in Safari anyway" escape hatch | Safari and the home-screen app have separate storage, so data entered before installing is stranded in Safari, where it can also be evicted. Android and desktop share storage, so they get only a hint. |
| 2026-10-03 | Export through the Web Share API with files, falling back to a download; retry button if Safari rejects the share | A plain download is awkward in an installed iOS app. The share sheet saves straight to Files or iCloud Drive. |
| 2026-10-03 | Backup reminder triggers on time (30 days with changes) or volume (50 changed entries), not time alone | Heavy use can put many entries at risk well before 30 days pass |
| 2026-10-03 | Import is replace-only, but warns with a count when the backup is older than current data and offers to back up first | Merging is complex and error-prone; the warning covers the main risk of restoring a stale file over newer data |
| 2026-10-03 | Add `Goal.openingCents`; opening amounts count toward the savings balance but never toward any month's net | The `savedCents` invariant needs a stored opening amount, and pre-existing money isn't this month's saving |
| 2026-10-03 | Goals are earmarks inside the savings balance. Free savings = balance − active goals' saved amounts. Writes that would make free savings or the balance negative are refused | Keeps goal totals from claiming money that isn't there; one clear rule for every write path |
| 2026-10-03 | Archiving asks whether the goal's money was spent. "I spent it" records a linked withdrawal; "Keep it in savings" frees it as free savings | A finished goal's money is often already spent; freeing it would show savings that don't exist |
| 2026-10-03 | A linked movement's goal and kind can't be edited; delete and re-add instead | Avoids two-goal recomputation in one edit and keeps edits simple to validate |
| 2026-10-03 | Deleting a goal while keeping its movements can lower free savings, and that choice is disabled when free savings can't cover it | Withdrawals since creation can exceed saves; the message and the refusal rule must handle that case |
| 2026-10-03 | Build and test locally first; GitHub repo, CI and Pages hosting come only in the final Publish phase | Owner's choice: get the app right before it's public. Real-phone install and offline tests need HTTPS, so they move to the Publish phase. |
| 2026-10-03 | Publish after Phase 3. Publish becomes Phase 4; the nice-to-haves become Phase 5, optional and after launch | The safety net is the last thing launch needs; recurring entries and custom categories are better designed after real use |
| 2026-10-03 | Base path comes from a `BASE` env variable from Phase 0, and the build is tested at `/pocket-ledger/` locally | Changing the base at publish time would change asset paths and service worker scope after all offline testing was done |
| 2026-10-03 | Single-entry add, edit and delete happen at once with a 6-second Undo toast; confirmation sheets stay for goal archive/delete, import and delete all | Undo protects against mistakes without slowing everyday logging; undo follows the same savings rules as any write |
| 2026-10-03 | Repository errors are typed; a failed write never clears the form; a database that won't open gets a full-screen message with Reload and a best-effort export | Storage can fail (full disk, private mode, version mismatch) and the app must not lose what was typed or leave the owner stuck |
| 2026-10-03 | Service worker uses the prompt pattern; updates apply from Settings or on next launch; IndexedDB `versionchange` and `blocked` are handled | Auto-reload could drop a half-filled form, and a second open window could block a schema migration |
| 2026-10-03 | Amounts use a text field with `inputmode="decimal"` and one parser: the last `,` or `.` followed by 1–2 digits is the decimal mark; 3 digits means thousands; maximum 99,999,999.99 | `type="number"` rejects `12,50` in some browsers and invites floats; one tested rule covers Greek and English input |
| 2026-10-03 | Expense form is amount first, with the 4 most recent categories as chips, a "Today" chip and a collapsed note; Enter submits; "Add expense" PWA shortcut | Hits the under-5-second goal: amount, chip, Add |
| 2026-10-03 | Entry dates can't be in the future, and "today" is recomputed on visibility, focus and every minute | Future entries landed in months the picker can't show; an installed app left open for days used a stale date |
| 2026-10-03 | Goal plan counts calendar months from a start month through the due month and rounds the monthly amount up to the cent. The start month is next month once the goal has had a contribution this month, and the plan line names it ("€120 a month from November") | Makes the plan exact and avoids a figure that silently changes after a contribution |
| 2026-10-03 | The Net tab stat and chart both show net to savings (saves − withdrawals), drawing negative months below a zero line | The stat and chart disagreed, and an "I spent it" withdrawal made the stat negative while the chart looked normal |
| 2026-10-03 | CLAUDE.md lists prototype behavior that must not be ported; no import of prototype data | The prototype syncs remotely and uses floats; the owner has no real data in it |
| 2026-10-03 | CSV export uses a UTF-8 BOM, `;` and decimal commas in comma-decimal locales, and escapes formula-like cells | Opens correctly in Excel with Greek settings and blocks formula injection from notes |
| 2026-10-03 | Pages build is an `npm run build:pages` script instead of an inline `BASE=…` env prefix; on iPhone the Add button must stay above the decimal keypad | Inline env syntax fails on Windows; the iPhone decimal keypad has no return key, so Enter can't be the only fast way to submit |
| 2026-10-03 | Build without npm installs: esbuild, TypeScript, tsx and Playwright only; no Vite, React, Dexie, vite-plugin-pwa, Vitest, ESLint or Prettier | The build environment the owner uses from their phone has no npm registry access, and only these tools were available. They are still pinned in `package.json`, so `npm install` works on a normal computer. |
| 2026-10-03 | No UI framework; screens are plain TypeScript with small DOM helpers | React's type definitions weren't available for strict TypeScript. Five tabs don't need a framework, and the app stays small. |
| 2026-10-03 | Own IndexedDB layer behind a `Store` interface, with an in-memory adapter for Node tests and a shared contract test run in Chromium | Replaces Dexie and fake-indexeddb while keeping repository rules fully testable in Node |
| 2026-10-03 | Hand-written, build-generated service worker with the prompt update pattern | Replaces vite-plugin-pwa with the same behavior: precache, offline, wait for the owner before updating |
| 2026-10-03 | Lint is strict `tsc` plus a script that enforces the non-negotiables (no float parsing of amounts, no UTC date parsing, no `window.confirm`, no `innerHTML` with data, no external URLs) | ESLint and Prettier weren't available; these checks guard what matters most for this app |
| 2026-10-03 | System font stacks instead of self-hosted Plex and Bricolage | Font packages couldn't be installed; system fonts load instantly and work offline. Self-hosted fonts can be added later. |
| 2026-10-03 | Phase 0's phone check is screenshots of every tab at 375×812 and 375×667, light and dark; a real phone over Wi-Fi is checked in Phase 4 | The owner builds from a phone, so there's no computer to run the dev server on the same Wi-Fi |
| 2026-10-03 | Precache fetches use `cache: "reload"` | The browser's HTTP cache could otherwise hand the service worker a file from the previous version, mixing two versions offline |
| 2026-10-03 | IndexedDB rules: no non-IDB awaits inside a transaction; `MemoryStore` is all-or-nothing like IndexedDB; contract tests in Chromium now, WebKit on a real iPhone in Phase 4 | Without Dexie, transaction safety is our own code. WebKit can't be downloaded in the build environment, so Safari behavior is checked on the device. |
| 2026-10-03 | The app is for phone and PC. Each device keeps its own data; the owner moves it with a backup file ("Send to my other device" / "Open from my other device"). No automatic sync | Keeps all data on the owner's devices with no account or server. Automatic sync would need a sync service. |
| 2026-10-03 | Import decides "safe to restore" from state lineage: each export gets a state id, files carry the last 50 ids, and a device is safe only if it has no unsent changes and its current state is in the file's lineage | A counter alone is reset by a routine backup or by a file that was sent but never opened, so changes could be lost without a warning. Reusing the id when nothing changed avoids false warnings from repeated backups. |
| 2026-10-03 | At 900px and wider, a left side menu replaces the bottom tab bar | A bottom tab bar is a phone pattern; on a PC a side menu uses the width and suits a mouse |
| 2026-10-03 | Manifest has no fixed orientation | A portrait lock makes no sense for an installed PC app or a tablet |
| 2026-10-03 | The unsent-changes warning lists what would be lost (up to 10 entries, then a count; deleted entries and goal or budget changes as counts) with a "Copy list" button; import stays replace-only | A count alone doesn't let the owner re-enter what they'd lose; a real merge isn't worth its risk before launch |
| 2026-10-03 | Repositories load all four tables in every write transaction, compute the change with pure functions, recompute every goal's `savedCents`, check the savings rules, then write | One code path for every write; the tables are small for one person, and it makes the "no other awaits in a transaction" rule easy to follow |
| 2026-10-03 | Savings rules compare before and after: a write is refused only if it makes free savings or the balance negative and worse than before | Imported data can already be inconsistent; refusing every write then would lock the owner out |
| 2026-10-03 | `InputError` joins the typed errors for invalid input; errors thrown by our own code pass through a transaction unchanged, and only storage-engine errors are mapped to `QuotaError` or `StorageError` | Screens need to tell "fix what you typed" apart from "storage failed", and bugs shouldn't be disguised as storage failures |
| 2026-10-03 | Only the most recent write can be undone; any newer write, in this window, makes the old token invalid. A write from another window can make an undo break a savings rule, and then it is refused | Matches SPEC Undo; the rule check keeps undo safe when two windows are open |
| 2026-10-03 | Lineage states carry `at`, the time this device took the state on (its export or its import). The "what would be lost" cutoff is the `at` of this device's newest state the file also has | Lists only what the other device really lacks, so re-entering from "Copy list" doesn't create duplicates. Using this device's own times avoids mixing two devices' clocks. |
| 2026-10-03 | Budgets get `updatedAt`; a `deleteLog` of timestamped entry, goal and budget deletes (cleared on import, max 2000) replaces the delete and goal/budget counters | Counts must be compared with the cutoff, and a single counter can't be |
| 2026-10-03 | The restore preview offers "Save a copy first", not "Send them first" | Without a merge, sending this device's data only moves the same warning to the other device; a saved copy makes any wrong choice recoverable |
| 2026-10-03 | Currency, locale and the recent-category lists travel with the data; theme, device fields, backup dates, snooze, the install acknowledgement and all sync fields stay on the device | One device's theme shouldn't overwrite the other's, and sync fields describe the device, not the data |
| 2026-10-03 | Counted changes: entries, undos, goals, budgets, currency and locale. Not counted: import, its `savedCents` repair, migrations, recent-category lists, per-device settings. A goal's derived `savedCents` doesn't change its `updatedAt` | Prevents a false warning right after a clean import, and counts the currency, which travels with the data |
| 2026-10-03 | Screens stay mounted after their first visit and are shown or hidden; only the visible one re-renders on a data change, the others when shown | Half-typed forms survive switching tabs, and a write never re-renders five screens |
| 2026-10-03 | The date chip is a native date input laid invisibly over the chip | Tapping it opens the phone's own date picker (best on iPhone), and `max` keeps future dates out |
| 2026-10-03 | Sheets use `<dialog>` with `showModal()`: bottom sheet on phones, centered on PCs | Native focus trapping, Escape and backdrop; no confirm() anywhere |
| 2026-10-03 | After adding an entry, the date goes back to today | A past date picked once shouldn't silently apply to the next entries |
| 2026-10-03 | Small phones (≤700px tall) get tighter form spacing; an e2e test checks that "Add expense" ends above a 260px keypad on 375×667 | SPEC Fast entry: the iPhone decimal keypad has no return key, so the button is the only way to submit |
| 2026-10-03 | The speed check runs at about 60 ms per add, edit or undo with 10,000 entries in Chromium; no optimisation needed yet | Well under the 150 ms target; a real older iPhone is checked in Phase 4 |
| 2026-10-03 | The Settings screen (gear in the header) arrives with Phase 3, together with backup, CSV and updates | Phase 2 has nothing to put in it yet besides currency and theme |
| 2026-10-03 | Money and amount fields follow the device's locale (12,50 € on a Greek phone); dates and month names are always English (`en-GB`: "3 Oct", "October 2026") | The app's words are English, so Greek month names would mix two languages; the decimal comma is what a Greek keyboard types |
| 2026-10-03 | Pills use their own text tokens (`--warn-ink`, `--bad-ink`) on a tint mixed over the surface; a test computes WCAG contrast from tokens.css for every text pair in both themes | Phase 2's amber pill was 4.12:1, under AA; the test keeps every pair at 4.5:1 or more |
| 2026-10-03 | A reached goal's main button is Archive; the archive sheet gives "I spent it" and "Keep it in savings" equal weight | Avoids inviting more money into a finished goal, and a quick tap shouldn't record a withdrawal |
